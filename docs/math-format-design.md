# 公式格式化设计

状态：已实现。验证范围见文末。

## 范围

Obsidian 的 `$$` 公式块没有格式化工具。Linter 只处理 `$$` 所在的行和块前后的空行，块内内容一律跳过；Prettier 一类的 Markdown 格式化器也把公式当作不透明文本。本功能只格式化块内的 TeX，目标是提高可读性：

- 每个环境缩进一级。
- 对齐环境中，每行公式单独占一行。
- 各行的 `&` 上下对齐。
- 去掉行尾空格。

入口：

- 命令 **Format math block**：光标位于 `$$` 块内时可用，编辑器右键菜单中也有。
- 命令 **Format all math blocks in note**：格式化整篇笔记，完成后用通知报告格式化了几个块、跳过了几个块。

不包括行内公式 `$…$`、`\[…\]`（Obsidian 不渲染）和代码块中的 TeX。

## 规则

唯一的硬约束是渲染结果不变：只移动大括号之外的空白，绝不增删或调换 token。

- **分词与 MathJax 4 一致。**
  - `{…}` 整体作为一个 token，`\text{}` 等分组的内容原样保留。
  - `\begin{name}` 吸收它的参数：`array` 的 `[pos]{cols}`、`alignat` 的 `{n}`、`aligned` 的 `[t]`。这些参数前可以有空白。
  - `\\` 只在紧跟着 `*` 或 `[…]` 时才把它们当作参数。中间隔着空格或换行时，`[…]` 属于下一行的内容。这条规则是在语料中发现两处渲染差异后，用 `MathJax.tex2mml` 实测确定的。
- **环境分为三类。**
  - 对齐环境：拆行，并按 `&` 对齐。包括 `aligned`、`align`、`alignat`、`split`、`cases`、各种 `matrix`、`array` 等。
  - 行环境：只拆行。包括 `gathered`、`gather`、`multline`、`CD`。
  - 其他环境：只缩进。
- **块级与行内。**
  - `\begin` 位于行首，或环境跨越多行时，按块级排版：`\begin` 所在行之前的文字原样保留（如 `f(x)=\left\{\begin{matrix}`），`\end` 之后同一行的内容跟在 `\end` 后面。
  - 单行内写成的小环境（如 `\begin{pmatrix}1&2\end{pmatrix}`）原样保留。
- **对齐方式。**
  - 单元格之间统一用 ` & ` 分隔；以关系符开头的单元格紧贴 `&`，写成 `&=`。
  - 列宽按显示宽度计算，东亚全角字符算 2 列。
  - 一行中包含跨多行的子环境时，这一行不参与对齐。
  - 行首的 `\hline`、`\hdashline` 单独占一行。
  - 行尾 `\\` 默认不对齐，因为长行会把短行的 `\\` 推到很远。
- **以下块原样保留，状态为 skipped。**
  - 块内有空行。
  - 大括号或环境不配对。
  - 出现游离的 `$`。
  - 对齐环境内有 `%` 注释时只重新缩进，因为注释会吞掉同一行后面的内容。
- **块的定位。**
  - 开头的 `$$` 位于行首、结尾的 `$$` 位于行尾，且不在 frontmatter 和代码块内。
  - 在 callout 和引用块中，块内每一行都必须带有与首行相同层数的 `>`。不满足的块整体跳过，但仍然一直跳到配对的 `$$`，避免把结尾的 `$$` 误当成下一个块的开头。
  - 输出时保留引用标记（规范为 `> `）或列表缩进。
- **单行块。**
  - `$$x$$` 这类格式化后仍是一行的块，原样保留。
  - 含块级环境的单行块，展开成多行，`$$` 各占一行。

## 决策

- **自己实现，不用 latexindent、prettier-plugin-latex 或 tex-fmt。**
  - latexindent 需要 Perl 和 YAML::Tiny、File::HomeDir 等模块，只能在桌面端通过子进程调用；而且 macOS 上从 Dock 启动的 Obsidian 拿不到 shell 的 PATH。
  - prettier-plugin-latex 会把 `$$` 改写成 Obsidian 不渲染的 `\[…\]`，并给所有下标加花括号（`C_1` → `C_{1}`）。
  - tex-fmt 有 WASM 构建，但没有发布到 npm，而且是否对齐 `aligned` 没有文档说明。
  - 自己实现可以在移动端使用、不改写原有写法，并能用库内全部公式回归验证。
- **单元格内部的空白原样保留，只合并连续空白。** 输入是 `a&=b`，输出就是 `a &=b`，不擅自补空格。
- **一次撤销即可还原。** 所有改动放在同一个 `editor.transaction` 中提交；光标位于被格式化的块内时，保持在原来那一行。
- **设置。** 缩进可选 2 或 4 个空格，`&` 对齐默认开，行尾 `\\` 对齐默认关。

## 宿主依赖

- 编辑器 API：`editor.transaction`、`posToOffset`、`offsetToPos`。
- 工作区事件：`editor-menu`。
- 对齐效果依赖 Obsidian 在源码中用等宽字体显示公式（`.cm-math` 使用 `--font-monospace`）。中文回退到其他字体后，宽度不一定恰好是 2 列，因此只能大致对齐。

## 验证

2026-11-11，macOS，Obsidian 1.14.5：

- `npm test`：模型 13 项通过。
- `node scripts/test-math-format.mjs <dev-vault>`：8 项通过。覆盖命令只在公式块内可用、只改光标所在的块、光标保持在原行、一次撤销完全还原、callout 中的块、跳过含空行的块、通知计数、幂等。
- spacetime 全库语料：86 篇笔记共 1427 个 `$$` 块。
  - 结果：改动 346 个，不变 1060 个，跳过 21 个（全部因为块内有空行）。
  - 等价性：每个改动的块都用 Obsidian 的 MathJax 4.1.3 `tex2mml` 分别生成格式化前后的 MathML，去掉回显源码的 `data-latex` 和 `alttext` 属性后比较，全部一致。
  - 幂等：格式化两次没有变化。
  - 第一轮发现 2 处不一致，都是 `\\` 换行后紧跟以 `[` 开头的行，已按 MathJax 的实际规则修正。

未验证：移动端、pop-out 窗口、MathJax 以外的渲染器（如导出 PDF 时）、`\cline` 等少见的规则命令。
