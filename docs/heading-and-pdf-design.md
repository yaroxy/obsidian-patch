# 标题等级和 PDF 导航设计

标题等级提示和 PDF 导航已实现，2026-11-12 在 macOS、Obsidian 1.15.0 验证。开发版已实现章节标题编号。分页分割线实验保留在 `pdf-pagination-prototype.md`。

## 标题等级提示

H1～H6 标签固定在标题区域末端。标签栏宽 2rem，与标题文字之间预留与左侧编号相同的最小间隔。默认开启，在 Editor 分组的 Heading levels 中切换。

实时预览的普通正文标题把主题提供的额外内边距上下平分。例如原本上方 16px、下方 0px 的标题改为各 8px。原生的空行例外仍然生效。阅读视图在段落、引用、代码块、列表或表格之后遇到正文标题时，将原先上下两种外边距取平均值。文档边界仍使用阅读器的原生裁边规则。

等级标签和章节编号都以标题的第一行行高定位。行高在标题上解析，再传给使用较小字号的标签，随标题级别、字体和缩放更新。当前行高亮条沿标题内容的全部可见行延伸，上下间距都留在高亮范围之外。

从左到右依次为原生行号、Git 变更标记、当前行高亮条、章节编号、标题和等级标签。行号、编号和等级与标题首行对齐。单行新增或修改标记与高亮条使用相同的宽度和端点留白，随标题换行延长。同一变更块内相邻的同类源码行连成一根色条，仅整段首尾保留留白和圆角。未改动的行、变更类型切换和删除三角都构成段落边界。Git 栏保留逐行点击区域，删除三角定位在实际删除边界。编辑器只测量当前渲染的行，使用行的实际上下内边距；折叠按钮的空间取自 Obsidian 的折叠边距。行号和 Git 栏可分别隐藏。

阅读视图使用作用于 Markdown 视图的 CSS 伪元素。Live Preview 和源码模式使用 CodeMirror widget，按可见范围中的 Markdown 标题 token 建立，每行最多一个标签。修改内容、滚动和语法树更新时重建；开关通过 StateEffect 刷新已有编辑器。Markdown 代码围栏中的嵌套语法高亮也可能带有 header token，因此显式排除 codeblock 和 frontmatter token。Setext 下划线不会得到第二个标签。

标签不写入源码。阅读视图的文字内容保持原样，编辑器 widget 标为 `aria-hidden`。样式以每个 Markdown 视图为作用域，覆盖 Callout 渲染出的标题；打印 DOM 不具有这个作用域，打印样式也排除标签。

`@codemirror/language` 是构建期开发依赖；运行时与 state/view 一起保持 external，使用 Obsidian 提供的模块。state/view 仍由 Obsidian 的精确 peer 版本提供。编辑器装饰使用宿主支持的 [CodeMirror decorations](https://docs.obsidian.md/Plugins/Editor/Decorations)。

## 章节标题自动编号

章节编号在全库默认关闭。打开 Editor 分组中的 Heading numbering，可在实时预览和阅读视图的标题文字前显示编号。现有的 H1～H6 标签仍由原开关控制。编号只用于显示，Markdown 中保留原始标题，因此移动章节后仍可用 `[[#准备]]` 跳转。首版范围为笔记正文；大纲和 PDF 编号可独立评估。

例如，一篇笔记按顺序写有以下标题：

| Markdown 源文 | 启用后的显示 |
| --- | --- |
| `# 项目计划` | 项目计划 |
| `## 实施` | 1 实施 |
| `### 准备` | 1.1 准备 |
| `### 执行` | 1.2 执行 |
| `## 验收` | 2 验收 |

若首个正文标题是全文唯一的 H1，将它视作文档标题。其余情况从第一个正文标题开始编号，包括以 H2 开头的笔记和使用多个 H1 的文档。每个标题归到前面最近的、级别更高的已编号标题下；没有这样的标题时，从顶层接着计数。跳级时只计实际出现的层级，例如上例将“准备”从 H3 改成 H4 后仍显示为 1.1。ATX 和 Setext 标题按同一规则处理，引用块、Callout、代码块和嵌入笔记中的内容不参与宿主笔记计数。

两种视图应按整篇笔记的正文顺序计算编号，再按源码位置装饰可见标题。实时预览以当前编辑缓冲区为准，以便插入、移动和撤销章节时立即更新。验收时应从长笔记中段打开，折叠再展开前面的章节，并检查重复标题和原有标题链接的跳转目标。

整篇笔记的自动编号共用一栏。编号和标题文字各自对齐到本栏的行首。在中文笔记中，`9`、`9.1` 和 `10` 都从同一左边缘开始，较短编号的右边留白。标题首字与换行后的文字也保持左对齐。栏宽按整篇笔记所有自动前缀的字形宽度计算，使用笔记库的正文字体，随字号缩放；更换字体或字体加载完成后重新测量。实时预览和阅读视图都把原生折叠箭头的点击区域留在编号之前。特别长的编号可在栏内折行，标题保留自己的字号。设置样文使用相同规则。手写编号沿用原文排版。

每个自动编号都有一小块等宽的圆角底色，以便辨认显示区域。底色用主题的页面背景混入 12% 的正文文字色，在浅色页面上略深，在深色页面上略亮。编号使用正文文字色，左右内边距计入编号栏宽。底色只覆盖编号所在的位置。

### 从用途选预设

| 使用场景 | 章 → 节 → 小节的显示示例 | 计数方式 |
| --- | --- | --- |
| 技术文档、论文 | `1 引言` → `1.1 背景` → `1.1.1 范围` | 显示完整祖先路径，同级递增 |
| 中文报告 | `一、引言` → `（一）背景` → `1. 范围` | 每层使用自己的样式，在新父节下从头计数 |
| 书稿（后续设计） | `第一章 引言` → `第一节 背景` → `一、范围` | 中文计数加各层的固定前后缀 |
| 英文提纲 | `I. Introduction` → `A. Background` → `1. Scope` | 罗马数字、字母、阿拉伯数字混用 |
| 逐项评审、演讲提纲 | `1 引言` → `2 背景` → `3 范围` | 选定范围内的标题按文档顺序共用一个计数器 |
| 附录（后续设计） | `附录 A 数据` → `A.1 来源`，下一附录为 `附录 B` | 附录单独起算，子节引用附录字母 |

开发版提供十进制层级、中文报告、英文提纲和全文连续四个预设。设置页用同一段含两章的样文即时预览，能看到下一章开启时子编号如何重置。默认只需要选预设；起始标题级别、最大编号深度和首章起始值放在展开项中。笔记属性 `patch-heading-numbering` 可选一个预设或填 `false`，缺省继承库设置。因此可以只给一篇论文启用，也可以在全库启用后单独排除一篇日记。

### 同一份大纲，分别决定计数和排版

编号模型记录每个标题的源码位置、实际父标题和各层整数序号。层级模式按父标题重置，连续模式在整篇内递增。固定起始层级（例如 H2）时，更浅的标题用作章节分界，不显示编号；下一个分界里的顶层继续原来的顶层序列。最大深度之后的标题保留原样，也不占序号。新根章节可以从指定的正整数起算，子节默认从 1 开始。

跳级时沿实际标题树编号。例如同一章下先有 H4「材料」，再有 H3「方法」，两者在这棵树中都是该章的直接子节，依次得到 `1.1`、`1.2`。插入真实的 H3「准备」并把「材料」移到它下面时，「材料」变为 `1.1.1`。这条规则让每个祖先号都能对应到一个可跳转的标题。固定级别的文档可提供跳级诊断，交由作者补齐缺失标题。

高级样式建议在后续版本开放。每个有效层级选择计数类型（十进制、中文、大小写字母或罗马数字）、是否带父级路径、分隔符和前后缀。格式化数字时保留其整数值，`Z` 后接 `AA`，中文的 10、11、20 分别是「十、十一、二十」。罗马数字在 1～3999 之外回退为十进制并在预览提示。父路径取各级格式化的数字，不带「第」「章」等装饰，所以书稿和附录都能正确生成子节号。附录切换和「引言／参考文献整节免编号」建议支持显式标记，以适配重名、改名和不同语言的标题；免编号的子树也不占用下一个同级序号。

### 手写标题、分享和验收

先比较当前预设应产生的前缀及其分隔符。比较链接标题时取双链的显示文字，引用式链接用整篇笔记的引用定义解析。例如首章标题 `[[方案|1 方法]]` 保留一个「1」。若源标题已经是预期的 `1.2 背景`，只显示一次并正常占位。`2026 年度计划`、`I/O 模型`、`3D 打印` 保留完整词义。遇到与当前预设明显冲突的手写章节号（例如应为 `1.2`，源文写着 `7.3 背景`），在该笔记的编号预览中标出标题和预期值，暂停该笔记的自动前缀以免产生混合序列。用户可调整起始值、停用该篇编号，或整理手写标题。普通编辑、重新打开笔记和切换预设均不会删除手写文字。

首版在实时预览和阅读视图显示编号，源码模式、普通复制以及已有的 `[[笔记#标题]]` 使用原始文字。后续优先考虑「复制带编号的大纲」和 PDF 正文／书签编号，让分享文档使用同一份计算结果。PDF 先用原始标题建立跳转目标，再添加可见前缀。若需要带编号的 Markdown 文件，可提供显式导出副本并预览文内链接；直接重写原笔记还涉及外部笔记的引用和撤销，单独设计。

阅读视图为每个渲染文档缓存对应源码的索引，再按区段行号匹配标题。实时预览根据未保存缓冲区更新索引。滚动时 CodeMirror 只绘制可见装饰。用相同输入验证两种视图的编号，并覆盖首个 H1、多个 H1、H2 起笔、跳级、手写号冲突、Setext、折叠、重名链接、分屏、撤销和长笔记中段打开。发布前在桌面和移动端分别检查窄栏换行、折叠箭头、屏幕阅读器和复制出的实际文本。

### 开发版实现

笔记属性可以直接用下面的形式选中文报告，即使库级开关关闭也只给这篇笔记编号。四个预设值为 `decimal`、`zh-report`、`en-outline` 和 `continuous`，布尔值 `false` 表示在本篇关闭。属性缺省时继承库设置。

```yaml
---
patch-heading-numbering: zh-report
---
```

1. **提取正文大纲。** 两种视图复用图表检查已有的 Markdown 块解析器，根据当前源码产生 `{ level, line, title }` 记录。ATX 和 Setext 都生成一条记录。Obsidian 负责识别 YAML 属性，块解析器排除容器中的标题、代码、块注释和显示公式。先看完整大纲，才能判断首个标题是否为唯一 H1。
2. **计算整数序号。** 独立函数 `numberHeadings` 在遍历中维护父节的整数路径，按源码行返回标题、有效深度、前缀和手写号匹配结果。根节点的已计数子项数初始化为「首章起始值减一」。按顺序遇到标题时，从栈顶弹出所有级别大于或等于它的标题。留下的栈顶就是父节。给父节的子项数加一，追加到它的路径，再将新标题入栈。指定从 H2 开始时，H1 会清空当前祖先栈，保留根计数器。全文连续预设另用一个计数器，每个符合范围的标题只递增一次。
3. **套用预设。** 十进制把整数路径用点连接。中文报告六层分别采用 `一、`、`（一）`、`1.`、`（1）`、`a.`、`（a）`，英文提纲依次用 `I.`、`A.`、`1.`、`a.`、`(1)`、`(a)`。两者按有效深度取样式。每条记录保留原始标题，用预期前缀及其分隔符识别已有编号。遇到明确冲突时返回源码位置、实际号和预期号，供设置预览定位。
4. **显示在两个视图。** 实时预览用 CodeMirror widget 显示前缀。连续输入时先随编辑映射已有装饰，间隔 60 毫秒后用最新缓冲区重算整篇。阅读视图从后处理器的 `getSectionInfo()` 获取正在显示的源码和区段行号，每个文档在相同源码和设置下共用一次计算。更新前置章节时会刷新保留的标题元素。两种视图都用空元素的 CSS 伪元素绘制数字，原始标题文本、链接目标和普通复制结果保留。

下列样例覆盖模型和两种视图的层级规则。下表中 H4 和后面的 H3 都是「方法」的直接子节。若在「材料」前插入 H3「准备」，「材料」变为 `1.1.1`，后面的「验证」仍为 `1.2`。

| 源标题 | 十进制层级 | 中文报告 | 英文提纲 | 全文连续 |
| --- | --- | --- | --- | --- |
| `# 实验记录` | 实验记录 | 实验记录 | 实验记录 | 实验记录 |
| `## 方法` | 1 方法 | 一、方法 | I. 方法 | 1 方法 |
| `#### 材料` | 1.1 材料 | （一）材料 | A. 材料 | 2 材料 |
| `### 验证` | 1.2 验证 | （二）验证 | B. 验证 | 3 验证 |
| `## 结论` | 2 结论 | 二、结论 | II. 结论 | 4 结论 |

## PDF 导航

沿用原生 Export to PDF 对话框。PDF Export 分组提供两个默认开启的独立选项：

- Document outline：由原生导出器根据标题生成层级书签，显示在 PDF 阅读器的目录或书签面板。
- Heading links：将当前笔记内的标题链接恢复成指向打印 DOM 标题 ID 的链接。

原生流程会清除 `a.internal-link` 的 href。恢复链接必须在原生 `print()` 返回之后进行；普通 Markdown post processor 会执行得太早。

### 宿主方法的适配

`src/features/pdf-export.ts` 集中处理未公开的 `MarkdownView.printToPdf()`、导出弹窗的 `print()` 与 `printToPdfDesktop()`。弹窗的 `print()` 与 `printToPdfDesktop()` 绑定到对应实例，避免方法脱离对象后丢失接收者。捕获弹窗只在同步调用原生入口期间临时包装 `Modal.open()`，其调用仍使用当前弹窗作为接收者；通过属性描述符保存原函数及属性标志，并在 finally 中完整恢复，包括原生导出抛错的情况。宿主 `open` 不是可写的自有函数属性时退回原生导出。没有修改 IPC 或全局 Electron 导出方法。

大纲使用 `generateDocumentOutline` 和 `generateTaggedPDF`；前者在 [Electron 文档](https://www.electronjs.org/docs/latest/api/web-contents#contentsprinttopdfoptions)中仍标为实验性参数。打印参数的其余字段原样传递。功能仅在桌面端注册；宿主入口不存在时保留原生行为。卸载时恢复自己持有的入口；已经打开的弹窗通过 disposed 标志回到原生行为，避免重载后叠加包装。

这些是需要随 Obsidian 升级复核的内部接口；当前实际验证版本为 1.15.0。

### 标题与链接匹配

1. 从打印 DOM 获取主文档的 Markdown 标题，排除嵌入笔记的标题。按顺序与 metadataCache 的标题匹配，建立源码偏移到 DOM 标题的映射。
2. 保留已有且唯一的 ID，其余使用不会与现有元素冲突的 ID。
3. 链接路径与片段分别解码。带路径的链接通过 `getFirstLinkpathDest()` 确认目标就是当前文件，不能仅比较文件 basename。
4. 优先使用 `resolveSubpath()`，保留 Obsidian 对重复标题的匹配语义。无法原生解析时，再匹配常见 Markdown TOC 片段，如 `#target-heading`；重复片段带数字后缀。
5. 未找到标题、其他笔记、块引用和嵌入笔记内部的链接不转换。外部网址保持不变。

自定义 HTML 锚点、跨笔记合并导出和完整兼容任意 TOC 插件不在本次范围内。

## 设置页排序

一级分组名称与渲染函数统一登记，使用英文名称排序，再生成分组标题。当前顺序为 Callouts、Editor、HTML Tables、Line Width、Math Format、Patch Banner、Patch Icons、Patch Mermaid、PDF Export。组内相关设置保留原有组织方式。

## 验证与复跑

```sh
npm test
npm run build
node scripts/test-navigation.mjs /path/to/dev-vault
```

集成入口写入 `dev-vault/Patch Navigation Tests/` 中的专用样例，部署当前构建，并在结束时恢复插件设置、弹窗尺寸、原标签页和后台节流。所有集成测试共用运行入口，详见 `integration-testing.md`。`OBSIDIAN_CLI` 可覆盖原生 CLI 路径；PDF 校验需要 pypdf 与 pdfplumber，可通过 `PDF_PYTHON` 指定 Python，默认使用 `python3`。

本次检查覆盖六种标题等级、Setext、代码围栏排除、修改与单步撤销、滚动后的标题、设置开关、右对齐、520px 窄阅读宽度下的长标题，以及实际设置页分组顺序。
